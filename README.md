# Очистка заявок клиентов (Lead Cleaner)

CLI-скрипт для нормализации и дедупликации заявок из Excel/CSV/TXT.

## Как запустить свой файл

### Шаг 1. Один раз установить зависимости

**Windows PowerShell:**

```powershell
cd путь\к\lead_cleaner
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

**macOS / Linux:**

```bash
cd путь/к/lead_cleaner
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Перед каждым новым запуском активируй окружение:

```powershell
.\.venv\Scripts\Activate.ps1
```

```bash
source .venv/bin/activate
```

### Шаг 2. Положить свой файл в папку проекта

1. Скопируй Excel/CSV в папку `lead_cleaner` (туда же, где лежит `clean_leads.py`).
2. **Не меняй расширение вручную.**  
   - Excel оставь как `leads.xlsx` (или любое имя с `.xlsx` / `.xls`).  
   - CSV оставь как `leads.csv`.  
   Простое переименование `файл.xlsx` → `файл.csv` **не работает** — формат не меняется.
3. В файле должны быть колонки с точными названиями:

   | Имя | Телефон | Дата заявки | Источник |

### Шаг 3. Запустить очистку

Подставь **своё имя файла** вместо `leads.xlsx`:

**Windows PowerShell:**

```powershell
python clean_leads.py .\leads.xlsx --output-dir .\output
```

Примеры:

```powershell
python clean_leads.py .\заявки.xlsx --output-dir .\output
python clean_leads.py .\C:\Users\Имя\Desktop\leads.xlsx --output-dir .\output
python clean_leads.py .\data.csv --output-dir .\output
```

**macOS / Linux:**

```bash
python clean_leads.py ./leads.xlsx --output-dir ./output
```

Можно указать полный путь к файлу в любой папке — копировать в проект не обязательно:

```powershell
python clean_leads.py "D:\данные\заявки_март.xlsx" --output-dir .\output
```

### Шаг 4. Открыть результат

В папке `output/` появятся:

| Файл | Что внутри |
|------|------------|
| `clean_leads.xlsx` | Чистые уникальные заявки + лист «Статистика» |
| `problem_leads.xlsx` | Все проблемные строки с причинами |
| `processing_report.json` | Краткая статистика в JSON |

### Проверка на тестовом примере

В репозитории есть готовый `sample_input.csv`:

```powershell
python clean_leads.py .\sample_input.csv --output-dir .\output
```


## 1. Что делает скрипт

Принимает файл с колонками `Имя`, `Телефон`, `Дата заявки`, `Источник` и:

- нормализует телефоны к виду `+7XXXXXXXXXX`;
- нормализует имена и даты;
- удаляет дубликаты по телефону (оставляет **первую** строку исходного файла);
- сохраняет чистые уникальные заявки;
- сохраняет все проблемные строки с причинами (ничего не теряется молча);
- пишет краткий отчёт со статистикой.

## 2. Требования

- Python 3.10+
- Зависимости из `requirements.txt`: `pandas`, `openpyxl`, `python-dateutil`, `pytest`

## 3. Формат входного файла

Поддерживаются: `.xlsx`, `.xls`, `.csv`, `.txt`.

Обязательные колонки (имена должны совпадать):

- `Имя`
- `Телефон`
- `Дата заявки`
- `Источник`

Если Excel случайно назван `.csv`, скрипт попробует распознать его по содержимому и прочитает как Excel (с предупреждением). Надёжнее всегда оставлять правильное расширение.

## 4. Правила нормализации

### Телефон → `+7XXXXXXXXXX`

- Удаляются пробелы, скобки, дефисы и прочие нецифровые символы.
- `8…` / `7…` (11 цифр) → `+7` + 10 цифр.
- Ровно 10 цифр → `+7` + эти цифры.
- Иначе номер **не угадывается** и считается некорректным.

Примеры:

- `8 (999) 123-45-67` → `+79991234567`
- `+7 999 123 45 67` → `+79991234567`
- `9991234567` → `+79991234567`
- `12345` → невалидный

### Имя

- Trim, сжатие пробелов.
- Каждое слово: первая буква заглавная, остальные строчные.
- Дефисы сохраняются: `анна-мария` → `Анна-Мария`.
- Пустое / `-` / `нет` / `n/a` → отсутствие имени.

### Дата → `YYYY-MM-DD`

Поддерживаются Excel datetime, `DD.MM.YYYY`, `DD-MM-YYYY`, `DD/MM/YYYY`, `YYYY-MM-DD`, даты со временем, текстовые русские месяцы (`15 февраля 2024`).

Время отбрасывается. Нераспознанная дата **не подменяется** текущей — помечается как `битая дата`.

## 5. Как обрабатываются дубликаты

- Ключ дедупликации — **нормализованный** телефон.
- Остаётся **первая** встреченная строка исходного файла (детерминированно).
- Повторы попадают только в `problem_leads.xlsx` с причиной `дубликат телефона`.
- В колонке `Дубликат строки` — номер исходной строки-оригинала.

## 6. Как интерпретировать проблемные строки

В `problem_leads.xlsx` попадают строки с хотя бы одной проблемой:

| Причина | Значение |
|---------|----------|
| `некорректный телефон` | Нет валидного `+7` + 10 цифр |
| `отсутствует имя` | Пустое / бессмысленное имя |
| `битая дата` | Дату не удалось распознать |
| `дубликат телефона` | Номер уже встречался ранее |

Несколько причин пишутся через `; `.

### Правило про битую дату

- Строка с **валидным телефоном и именем**, но битой датой:
  - остаётся в `clean_leads.xlsx` (как контакт);
  - **одновременно** попадает в `problem_leads.xlsx` с причиной `битая дата`;
  - статус: `в чистых с замечаниями`.
- Без валидного телефона — **только** в проблемный файл.
- Дубликаты — **только** в проблемный файл.

Колонка `Исходная строка` — номер строки во входном файле (1 = заголовок, данные с 2).

## 7. Ограничения решения

- Только российские номера в формате `+7` + 10 цифр; иностранные не нормализуются.
- Опечатки в именах не исправляются.
- Даты не «угадываются» при неоднозначности сверх поддерживаемых форматов.
- Обязательные колонки должны называться точно: `Имя`, `Телефон`, `Дата заявки`, `Источник`.
- Берётся первый лист Excel / таблица целиком.
- CSV/TXT: разделители `;`, `,`, таб, `|`; кодировки UTF-8, UTF-8-SIG, cp1251.
